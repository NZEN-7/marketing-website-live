# Setting up lead capture, step by step

About 20 minutes. You need to do this yourself, in a browser, signed in as
**nickz@thermaldawn.com** and no other account. Reasons in step 0.

The code is here, in the website repo, because it is coupled to `api/lead.js`:
that file writes the emails this script reads. `npm run test:parser` proves the
two still agree. The CSV it writes to lives in Drive at `Sales +/CRM/leads.csv`,
and how to triage it is `LEADS.md` there.

---

## Step 0: why it has to be you, and the Workspace bit

An Apps Script only ever sees the Gmail and Drive of **the account that owns
it**. Built under a personal Gmail or a contractor's account it reads an empty
mailbox, writes nothing, and looks like it is working. It must be created
while signed in as the Workspace account that receives the notifications.

This also keeps the PII promise: customer details never leave the Workspace,
because the script runs inside it. That is the whole reason for using Apps
Script rather than Zapier or an ESP.

**Because thermaldawn.com is a Google Workspace domain, not a personal Gmail,
two admin settings can block this. Check them first, at admin.google.com:**

1. **Apps Script must be allowed.**
   Admin console → Apps → Additional Google services → **Apps Script** → make
   sure it is **ON for everyone** (or at least for your account). If it is off,
   the editor will refuse to run anything and the error will not explain why.

2. **API access / third-party app control.**
   Admin console → Security → Access and data control → **API controls**.
   If "Trusted apps" is restricted, an *internal* script you own is normally
   still fine, but if authorisation in step 5 fails with an admin-policy error,
   this is where it is blocked. You are a super admin, so you can allow it.

You are both the admin and the user here, so nothing needs approving by anyone
else. Just know where to look if step 5 refuses.

**One thing to decide now, not later:** this script will be owned by your
personal Workspace account. If that account is ever suspended or closed, the
script and its triggers die with it and lead capture stops silently. For now
that is an acceptable trade. When there is a second person in the business,
move it to a shared account and write that down.

## Step 1: get the CRM folder id

Open `Sales +/CRM/` in Drive in a browser. The URL ends in a long string:

```
https://drive.google.com/drive/folders/1AbCdEf...
                                       ^^^^^^^^^^ this is the folder id
```

Copy it. Confirm `leads.csv` is in that folder, with its header row. It is
already created.

---

## Step 2: create the script project, two files

1. Go to **script.google.com**, signed in as nickz@thermaldawn.com.
2. **New project**.
3. Rename it (top left) to **Thermal Dawn lead capture**. A project called
   "Untitled project" is one nobody dares delete in two years.
4. Delete the placeholder `myFunction` code.
5. Paste in **`lead-capture.gs`** from this folder.
6. Add a second file: **+** next to Files → **Script** → name it
   `lead-parser` → paste in **`lead-parser.gs`**.
7. **Save** (the disk icon, or Ctrl+S).

Two files, not one, on purpose. The parser is separate so it can be run under
Node against emails generated by `api/lead.js` itself; that is what
`npm run test:parser` does. Apps Script files share one global scope, so
`captureLeads` can call `parseLead` with nothing to wire up.

---

## Step 3: paste the folder id

In `lead-capture.gs`, near the top:

```js
FOLDER_ID: 'PASTE_THE_CRM_FOLDER_ID_HERE',
```

Replace that with the id from step 1, keeping the quotes. Save.

## Step 4: run the config test first

In the toolbar function dropdown choose **testConfig**, then **Run**.

This does not write anything. It only proves the script can see the folder, the
file, the parser and the mail. Run it before anything that writes. `Parser
loaded: true` in the log means step 2.6 worked; `false` means the second file
is missing or misnamed.

---

## Step 5: authorise it (the confusing screen)

The first run asks for permission. This is where people stop, because Google
shows a warning that looks alarming and is not:

1. **Review permissions** → choose your account.
2. You will see **"Google hasn't verified this app"**. This is expected. The
   "app" is the script you just pasted; unverified only means you have not
   submitted it to Google for review, which is not required for your own
   internal script.
3. Click **Advanced** (small link, bottom left).
4. Click **Go to Thermal Dawn lead capture (unsafe)**. Also expected wording.
5. Review what it asks for and **Allow**:
   - read/modify Gmail (it needs to read notifications and apply labels)
   - see/manage Drive files (it needs to append to leads.csv)

If this step fails with a message about your organisation's policy, that is the
admin setting in step 0.2.

**Check the log:** View → Logs (or Ctrl+Enter). You want to see the folder name,
`leads.csv`, and a count of matching threads. If threads is 0, the query found
nothing: check you are signed in as the right account.

---

## Step 6: the first real run, deliberately by hand

Choose **captureLeads** in the dropdown, then **Run**.

This one writes. It will sweep the whole existing backlog, which is roughly 40
threads going back to July, so the first run is also the recovery of the August
capture gap. Do it once by hand and look at the result before automating it.

Then open `leads.csv` (download it, or view in Drive; **do not leave it open in
Sheets**, see the warning below) and check:

- Real names you recognise: Marion Saville, Peter Kershaw, Simon Radcliffe.
- No `qa-` or `deploy-check` rows; those are skipped as tests.
- `triage_status` is `New` on every row.
- Emails are lowercased, one row per submission.
- Contact-form rows have the customer's actual message in `comments`.

If something looks wrong, you can start over cleanly: delete every row from
`leads.csv` except the header, remove the `crm-captured` label from the threads
(Gmail → left sidebar → the label → select all → remove label), and run again.
The source emails are never modified, so nothing is lost by re-running.

---

## Step 7: set the trigger

Left sidebar → **Triggers** (clock icon) → **Add Trigger**, bottom right.

- Function to run: **captureLeads**
- Deployment: **Head**
- Event source: **Time-driven**
- Type: **Minutes timer**
- Interval: **Every 15 minutes**
- Failure notification: **Notify me immediately**

Save. That last setting matters: it is the only alerting there is.

---

## Step 8: prove it end to end

1. Go to the live site and submit a real form. Do **not** use a `qa-` address;
   those are skipped as tests and you will conclude wrongly that it is broken.
   Use a personal address you control.
2. Wait up to 15 minutes.
3. Check `leads.csv` for the new row.

That is the whole loop proven: website → email → Gmail → CRM.

## Living with it

**Is it running?** Run **showHeartbeat** by hand. It reports the last run time
and what it did. If `last_run_at` is hours old, the trigger has stopped. This
exists because a script that has silently died looks exactly like a quiet week,
and that ambiguity is what hid the August gap for three weeks.

**Never leave leads.csv open in Sheets** while the trigger is on. It is a CSV
with no concurrency protection: a save from Sheets can overwrite an append and
the lead is gone with no error. If you want to work in it, pause the trigger
first, or work on a copy.

**A message that will not parse** gets the `crm-capture-error` label and no row.
Search that label in Gmail occasionally. An empty label is the healthy state.

**If you change a field label in `api/lead.js`**, capture breaks. That layout is
a contract for exactly this reason. Run `npm run test:parser` and it fails
immediately, telling you which field; fix `LEAD_LABELS` in `lead-parser.gs`,
then **re-paste that file into the Apps Script project**. Nothing syncs it
automatically, and that is the one manual step in this whole thing.

**When the site moves off Wix**, nothing here changes. Both streams already use
the same field labels; the Wix stream simply stops arriving. Do not add a
"which site is live" switch, it would only be a thing to get wrong.
